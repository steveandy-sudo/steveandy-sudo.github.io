The course environment combined ROS 2 Humble, PX4 SITL, Gazebo, QGroundControl, and Micro XRCE-DDS. I developed the waypoint-mission package and integrated it with the existing offboard controller.

## Design choices

| Choice | Engineering purpose |
| --- | --- |
| Three-dimensional arrival distance | Advance targets using both horizontal and vertical position |
| Start, stop, and reset controls | Make the mission lifecycle explicit during integration and testing |
| Current-goal and mission-status reporting | Make target progression observable while debugging |
| Explicit ENU / local-NED modes | Handle the coordinate boundary between ROS poses and PX4 commands |
| Altitude checks before disarm | Gate the implemented land-then-disarm finish path on the reported vehicle state |

The archived configuration contains **nine waypoints** and a default **1.0 m arrival tolerance**. The exact configuration used in the demonstration has yet to be matched to a run record, and measured tracking-error statistics are unavailable.

## Coordinate and finish-state integration

The mission node supplies pose targets while the offboard controller performs vehicle-side conversion and command publication. During reproduction, **coordinate conversion must have one clearly defined owner**: the collected controller already converts ENU to NED, so the mission output mode and origin must be checked together.

The package implements `hold`, `land`, `disarm`, and `land_then_disarm` finish options. The final simulation demonstrated landing, while the exact launch configuration and landing-command receiver still need to be matched to that run. The [repository setup notes](https://github.com/steveandy-sudo/uav-waypoint-portfolio) document these integration points.

## What I learned

I learned to check arrival conditions and coordinate conversion alongside the mission logic. Reporting the current goal and mission state made the progression between waypoints visible during debugging.

A follow-up evaluation would record the target sequence, measured trajectory, arrival times, and landing event over repeated runs. Those records would allow calculation of tracking error, time to reach each waypoint, and completion rate.
