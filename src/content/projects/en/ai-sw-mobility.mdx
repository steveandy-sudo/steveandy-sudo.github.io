## From presentation to implementation

### Presenting the control strategy

I presented a strategy for **combining Pure Pursuit and Stanley** at a Team K.A.I. technical symposium sponsored by Hyundai Mobis. The presentation, prepared with Woojin Hwang, compared Pure Pursuit's lookahead-based steering with Stanley's heading- and cross-track-error feedback.

Our proposal was to combine their steering outputs and adjust the balance as driving conditions change. We discussed curvature and speed as inputs to this decision, gradual changes between controller weights, and a plan to evaluate the approach in ROS 2 simulation.

### Implementing the controller

After the presentation, I wrote and revised code for the combined controller. The implementation calculates both steering commands and blends them according to the driving phase: straight driving, corner approach, turning, or corner exit. Speed and upcoming path geometry also influence lookahead and the individual steering calculations.

Weight changes are gradual, and steering-angle and steering-rate limits constrain the final command. **Parameter tuning is ongoing**, with comparison tests and log analysis guiding the next revisions.

### Recognition

The presentation by **Woojin Hwang and Junghun Hwang** received the **Hyundai Mobis Technical Special Award, Autonomous Driving Division**, awarded in the name of **Konkuk University Team K.A.I.**

## Obstacle avoidance: diagnosis and correction

### Finding a coordinate–timestamp inconsistency

A cached path was stored relative to the vehicle at the time it was generated. Reusing those points after the vehicle moved, while assigning a new timestamp, made an old path appear to belong to the current vehicle frame.

I identified the problem, set the analysis direction, modified the code, and ran tests. The investigation used **four recorded drives** to compare planning horizon, return distance, path curvature, and clearance from obstacles. Synchronized MCAP/Foxglove visualizations placed recomputed candidate paths alongside the original camera and vehicle data. These comparisons were offline analyses of recorded conditions.

### Correcting reuse and checking regressions

I implemented **odometry-based reprojection** so a cached path is transformed from its saved vehicle pose into the current vehicle frame. The reuse logic preserves the original path as its reference and retains the original timestamp during pose-history gaps.

Regression tests cover reprojection, repeated reuse, and pose-history gaps, including a fixture built from recorded path and odometry samples. The fix was incorporated into the **team's main branch**.

I also updated the local planning horizon from 35 m to **45 m** based on the recorded-drive comparisons. The setting controls the planner's forward horizon, while return distance is configured separately. Both the reprojection correction and the horizon setting remain in the team's current main branch.

### Field troubleshooting with the team

My recent work combines **vehicle operation, log analysis, and proposals for software corrections** discussed with teammates. This brings observations from field runs into the team's review of obstacle behavior and path generation.

The team's latest integration work covers input-age checks before departure, stop-state and finish-line braking behavior, and steering alignment. Within that work, my main contribution continues to be obstacle-avoidance diagnosis and the link between recorded evidence, code changes, and field operation.

## AEB and vehicle integration

For the AEB course, perceived cone boundaries define a center path for the vehicle to follow. Detecting the red-cone entrance latches the stop request across perception updates. Input-age checks also trigger a stop request during stale-input conditions.

I tested the pipeline in Gazebo and used Foxglove to inspect the generated path, steering command, and stop state. Steering limits and the command interface connect the decision software to the vehicle's low-level control system.

## Technical report

I authored the **High-Level Control** section of Team K.A.I.'s competition technical report. It explains how the controller converts a target path, target speed, and stop request into commands for the vehicle.

The section covers the **50 Hz** control loop, hybrid steering, adaptive lookahead, steering constraints, and the interface to the low-level controller. I also conducted comparison tests and analyzed tracking errors and steering-command variation for the report.

## Initial simulation results

I conducted the comparison tests and analyzed the logs for **hybrid Pure Pursuit + Stanley versus Stanley alone**. The comparison used **the same Gazebo course segments at 6 m/s**, with route progress aligned to reduce differences in segment composition and travel distance.

| Metric | Change with hybrid tracking versus Stanley alone |
| --- | --- |
| Heading-error p95 | Approximately **14% lower** |
| Steering-error p95 | Approximately **7% lower** |
| Steering-command total variation | Approximately **10% lower** |
| Curved-section lateral-error p95 | Approximately **8% lower** |

Here, **p95** is the 95th percentile of the recorded error values. Steering-command total variation measures the accumulated changes in the steering command over the comparison segment.

These figures come from the **initial matched Gazebo comparison** documented in the team technical report. Subsequent development includes controller tuning, cached-path reprojection, regression tests, and vehicle trials.

I was responsible for **vehicle operation** during field tests of the updated software. With the cached-path reprojection and 45 m planning-horizon setting both applied, the vehicle **successfully avoided the obstacle and returned to the reference route**.
