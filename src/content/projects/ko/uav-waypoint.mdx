수업 환경은 ROS 2 Humble, PX4 SITL, Gazebo, QGroundControl, Micro XRCE-DDS로 구성되었습니다. 저는 웨이포인트 미션 패키지를 개발하고 기존 offboard 제어기와 연동했습니다.

## 설계 선택

| 선택 | 목적 |
| --- | --- |
| 3차원 도착 거리 | 수평 위치와 고도를 함께 고려해 다음 목표로 전환 |
| 시작·정지·초기화 명령 | 통합과 시험 과정에서 미션 실행 상태를 명확하게 제어 |
| 현재 목표점과 미션 상태 출력 | 디버깅 중 목표점 전환을 확인 |
| 명시적인 ENU/local-NED 모드 | ROS 위치 정보와 PX4 명령 사이의 좌표 변환 처리 |
| disarm 전 고도 확인 | 기체가 보고한 상태를 확인한 뒤 land_then_disarm 종료 절차 진행 |

보관된 설정에는 **웨이포인트 9개**와 기본 **도착 허용 오차 1.0 m**가 들어 있습니다. 최종 시연에 사용한 정확한 설정은 아직 실행 기록과 대조하지 못했으며, 측정한 추종 오차 통계도 없습니다.

## 좌표와 종료 상태 연동

미션 노드는 목표 위치를 제공하고, offboard 제어기는 기체 측 좌표 변환과 명령 발행을 수행합니다. 재현할 때는 **좌표 변환을 담당하는 곳을 명확히 정해야 합니다.** 보관된 제어기가 이미 ENU를 NED로 변환하므로 미션 출력 모드와 좌표 원점을 함께 확인해야 합니다.

패키지는 `hold`, `land`, `disarm`, `land_then_disarm` 종료 옵션을 구현합니다. 최종 시뮬레이션에서 착륙을 시연했지만, 당시의 정확한 실행 설정과 착륙 명령 수신 노드는 해당 실행 기록과 대조할 필요가 있습니다. [저장소의 실행 안내](https://github.com/steveandy-sudo/uav-waypoint-portfolio)에 이러한 연동 조건을 정리했습니다.

## 배운 점

미션 로직과 함께 도착 조건과 좌표 변환을 확인하는 방법을 배웠습니다. 현재 목표점과 미션 상태를 출력해 디버깅 중 웨이포인트 전환을 확인할 수 있었습니다.

후속 평가에서는 반복 실행마다 목표점 목록, 측정 궤적, 도착 시각과 착륙 이벤트를 기록하려 합니다. 이 기록으로 추종 오차, 목표점별 도달 시간과 완주율을 계산할 수 있습니다.
