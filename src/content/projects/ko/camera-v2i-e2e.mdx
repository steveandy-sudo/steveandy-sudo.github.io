## 연구 질문

**인프라 카메라 정보를 추가하면 주차 차량 뒤에 가려진 보행자에 대한 E2E 차량의 대응이 어떻게 달라지는가?**

프로젝트의 최종 목표는 이 방식을 실차에 적용하는 것이다. 도로변 카메라가 차폐 영역을 관측해 보행자 정보를 차량으로 보내고, 차량은 이를 차량 카메라 입력 및 차량 상태와 결합하는 구상이다. 교내 소형차 플랫폼에서는 시나리오와 시스템 기능을 시험하고, **Camera-only와 V2I 정보 활용 E2E 모델을 비교**할 계획이다.

이번 학기에는 조사와 예비 설계에 집중하며 정량 요구조건, 인터페이스, 측정 경계와 시험 절차를 구체화하고 있다. 별도의 소프트웨어 부분시험에서는 후보 모델 구조의 실행시간을 측정했다. 데이터 수집, 모델 학습과 차량 통합시험은 후속 단계에서 진행할 계획이다.

## 관련 연구 검토와 프로젝트 범위

UniV2X에서 차량·인프라 융합과 개루프 평가를 다룬 부분을 검토하고, 프로젝트 범위 설정에 참고할 수 있도록 내용을 요약했다. 축소 차량에서 계획 중인 폐루프 비교를 위해 단순화한 융합 방식을 제안했다.

비교 실험에서는 보행자 정보를 더 일찍 제공했을 때 차량의 감속 시점과 확보되는 정지 여유가 달라지는지 살펴볼 계획이다.

## 중간발표 예비 설계

팀 논의 후 시나리오, 보행자 위험도 평가, 제동 여유와 학습 데이터 요구사항을 담은 중간발표 자료를 작성했다. 이후 설계 검토에서는 AI를 활용해 문헌·계산·시험 절차를 검토하고 발표자료를 수정했다. 최근 작업에서는 정지 조건으로부터 허용 지연을 계산하고 시스템 측정 방법을 구체화했다.

| 설계 항목 | 현재 제안 |
| --- | --- |
| 대표 시나리오 | 통제된 직선 구간의 차량 1대, 보행자 1명, 차폐물 |
| 운행 조건 | 주간, 맑은 날씨, 건조한 노면, 저속 주행, 위치 추정과 V2I 수신의 정상 동작 |
| 인프라 카메라 | 도로 건너편의 높은 위치에서 관측하며, 현장에서 설치 위치·각도와 보행자 가시성 검토 예정 |
| 보행자 정보 | 위치, 속도, 관측 기반 위험도, 촬영 시각, 메시지 순서·유효성 정보 |
| 차량 주행계획 | 차량 카메라 입력 및 차량 상태 활용, V2I 정보 활용 모델에 인프라 정보 추가 |
| 출력 | 하위 제어기에 전달할 웨이포인트와 목표 속도 |

교내 시험에서는 주차 차량을 차폐물로 사용하고, 보행 표적이 도로변의 가려진 위치에서 차도로 이동하는 상황을 구성할 계획이다. 카메라 배치, 시야각과 보행자 가시성은 현장 검토 항목이다.

## 보행자 위험도와 목표 속도 라벨

예비 설계는 다음 세 요소를 결합한다.

- **보행자 상태:** 연석을 기준으로 한 위치와 도로에 접근하거나 도로에서 멀어지는 움직임.
- **경로 중첩:** 보행자 점유 영역과 차량의 계획 경로가 겹치는지 여부.
- **제동 여유:** 시스템 지연, 제동 거리, 안전 여유를 고려했을 때 확보되는 거리.

필요 정지 거리는 `d_req = v × T_system + D_brake(v) + M`으로 나타낸다. 팀은 차량의 제동 특성과 시스템 처리 시간을 측정해 설계값을 구체화할 계획이다.

전문가 규칙 기반 라벨 생성 계획은 이 정보를 바탕으로 **조기 감속, 경로가 점유된 동안의 정지 유지, 경로가 비워진 뒤의 재출발**을 정의한다. 두 E2E 모델에는 동일한 목표 라벨을 사용할 계획이다.

## 정지 조건에 따른 허용 지연 분석

차량이 정지에 필요한 거리를 확보하면서 허용할 수 있는 지연을 계산했다. 실차 적용 분석의 기준 속도는 <strong>30 km/h(약 8.33 m/s)</strong>로 두고, 감속 시작 이후 일정한 감속도가 유지된다고 가정했다.

`T_total ≤ (D − v² / (2a) − g) / v`

여기서 `D`는 촬영 순간 차량 앞부분에서 충돌영역 경계까지 남은 거리, `a`는 가정한 감속도, `g`는 요구 정지 간격이다. 문헌을 설계 참고자료로 삼아 감속도 1.5·2.5·3.5 m/s²를 비교했다. 아래 표는 **감속도 1.5 m/s²**, **정지 간격 후보 2 m**를 적용한 계산이다.

| 확보 거리 D | 계산한 전체 허용 지연 상한 |
| --- | --- |
| 30 m | 약 582 ms |
| 35 m | 약 1,182 ms |

이 값은 가정한 조건에서 계산한 시간 상한이다. 적용 차량의 제동 특성과 시나리오에서 확보할 수 있는 관측거리를 구체화해 최종 지연 목표를 정할 예정이다. 교내 플랫폼에는 별도의 운행·제동 조건을 적용한다.

전체 지연의 측정 범위는 **영상 촬영부터 실제 감속 시작까지**로 정의했다.

| 구간 | 측정 경계 |
| --- | --- |
| 인프라 | 촬영(`t0`)부터 보행자 상태정보 완성(`t1`)까지 |
| 통신 | 상태정보 완성(`t1`)부터 차량에서 메시지 전체 수신(`t2`)까지 |
| 차량 | 메시지 전체 수신(`t2`)부터 실제 감속 시작(`t4`)까지 |
| 제동 작동 | 제어 명령 적용(`t3`)부터 실제 감속 시작(`t4`)까지, 차량 구간에 포함 |
| 전체 | 촬영(`t0`)부터 실제 감속 시작(`t4`)까지 |

제동 작동지연은 지연 예산에 한 번 반영하고, 실제 감속이 시작된 뒤의 제동거리를 별도로 계산하도록 경계를 정리했다. 처리·전달·판단·작동 단계별 기록을 남기는 측정 계획이다.

## 후보 모델 실행시간 측정

차량 E2E 모델 후보인 <strong>OpenDriveLab의 TCP(Trajectory-guided Control Prediction)</strong>의 연산시간을 알아보기 위해 ChatGPT를 활용해 측정 시험을 준비하고 직접 실행했다.

| 항목 | 측정 조건 또는 결과 |
| --- | --- |
| 모델 가중치 | 무작위 초기화 |
| 하드웨어·연산 정밀도 | NVIDIA GeForce RTX 5070 Laptop GPU, FP32 |
| 소프트웨어 | Windows, Python 3.11.9, PyTorch 2.11.0+cu128 |
| 입력 | 영상 텐서 `1×3×256×900`, 상태 텐서 `1×9` |
| 반복 | 준비 실행 50회 후 600회 측정 |
| 측정 범위 | 준비된 CPU 입력 → GPU 전송 → 모델 순전파·동작 출력 계산 → CPU 출력값 반환 |
| 평균 / 중앙값 | 20.04 / 20.02 ms |
| P95 / 최대 | 21.88 / 24.65 ms |

무작위 가중치를 사용하는 후보 모델 구조의 실행시간을 측정한 결과다. 카메라 취득, 영상 전처리, V2I 융합, 스케줄링, 차량 전달과 실제 작동은 후속 파이프라인 측정 범위로 두고 있다. TCP는 검토 중인 모델 후보이며, 주행 성능과 두 모델의 비교는 후속 평가 항목이다.

## 인프라 공간 관계와 시간 정렬

예비 공간 설계에서는 호모그래피로 영상 관측값을 지면 평면에 대응시킨다. 보행자의 추정 위치와 차량 위치를 공통 로컬 ENU 좌표계로 표현한 뒤, 차량 좌표계로 변환하는 구상이다.

시간 처리 계획에서는 영상의 촬영 타임스탬프를 유지하고 **시계 동기화**와 **움직임 보상**을 구분한다. 처리·송신·수신·융합·제어 단계의 타임스탬프를 활용해 추후 지연 시간과 메시지 최신성을 분석할 계획이다.

현재 카메라 배치, 지면 기준점, 독립적인 정확도 검증, 타임스탬프 표기·처리 규칙을 설계하고 있다.

데이터 수집 계획은 동일한 주행에서 차량 영상·차량 상태·인프라 관측 정보를 함께 기록하는 방식이다. 학습·검증·시험 데이터는 **주행 또는 세션 단위**로 분리할 계획이다. 계획한 시나리오는 보행자 부재, 차량 경로 안팎의 정지, 접근, 횡단, 이탈을 포함한다.

교내 시험은 소형차 플랫폼의 직선 감속·정지를 중심으로 계획하고 있으며, 운행 조건으로 8 km/h를 검토하고 있다. 기반 모델, 학습과 제어 조건의 대응 관계를 확인하고 장면을 짝지어 시험 순서를 교대할 계획이다.

평가 항목은 사건별 지연(P50·P95·최대), 위치 편향·RMSE, 감속 시작 시점, 최종 정지 간격, 불필요한 감속, 필요한 감속의 누락, 접촉과 안전 개입이다. 통신에서는 메시지 손실, 연속 수신 공백, 연결 복구, 모델 전환 지연과 명령 연속성을 살펴볼 계획이다.

표본 단위는 독립 주행 또는 사건으로 정했다. 필요한 감속이 실제 발생한 사건의 지연 분포를 계산하고, 해당 반응이 발생하지 않은 사건은 별도로 집계할 계획이다. 반복 횟수와 정량 판정 기준은 후속 설계에서 구체화한다. 이를 통해 응답시간의 분포와 요구한 반응의 성공 비율을 구분해 살펴볼 수 있다.

## V2I 통신 방식 조사

인프라 컴퓨터와 차량 컴퓨터 사이의 통신 후보로 Wi-Fi를 통한 직접 UDP 송수신과 ROS 2/DDS를 조사하고 있다. 초기 접속, 관측 정보 도착 시간과 보행자 시나리오 구간 접근 중 수신 연속성을 검토한다.

현재 비교 기준은 다음과 같다.

- **메시지 최신성:** 관측 시점부터 사용 시점까지의 시간.
- **전달 지연:** 송신 시점부터 수신 시점까지의 시간.
- **수신 연속성:** 수신 공백, 메시지 누락·순서 뒤바뀜, 재연결 시 동작.

전용 Wi-Fi 네트워크와 다른 연결 구성을 팀 논의 후보로 검토하고 있다. 인프라 정보가 없거나 유효하지 않을 때 자체 E2E로 주행하고, 유효한 수신이 복구되면 협력 모델로 전환하는 구조를 설계했다. 모델 전환 지연과 명령 연속성은 향후 평가 항목이다. 통신 방식은 현재 **조사·설계 단계**에서 선정하고 있다.

## 후속 설계 과제

다음 단계에서는 통신 방식을 선정하고 보행자 상태정보 인터페이스를 구체화하며, 현장에서 카메라 가시성과 공간 정렬을 평가하고 플랫폼의 제동 특성과 파이프라인 지연을 측정한다. 이 결과를 바탕으로 지연 목표와 정량 판정 기준을 정할 예정이다. 이후 데이터 수집, 모델 학습과 소형차 폐루프 비교를 진행할 계획이다.
