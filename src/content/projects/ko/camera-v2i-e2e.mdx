## 연구 질문

**주정차 차량이 차량 카메라의 시야를 가릴 때, 인프라 카메라 정보로 보행자 검출과 감속을 얼마나 앞당길 수 있을까요?**

제안하는 시스템은 **1/5 크기 실험 차량**을 사용합니다. 도로변 카메라가 가려진 구역을 관찰해 보행자 상태를 차량으로 보내고, 차량의 E2E 계획 모듈은 이를 차량 카메라 입력과 결합합니다. 현재는 요구사항과 비교 구조를 정의하고 있으며, 구현, 학습, 실차 시험은 향후 진행할 계획입니다.

## 4주차 설계 현황

| V-model 단계 | 현재 산출물 | 진행 상태 |
| --- | --- | --- |
| L1: 사용자 요구 및 운행설계영역 | 어린이보호구역의 가림 시나리오와 초기 운행 조건 | 정의 완료 |
| L2: 시스템 요구사항 및 상위 설계 | 기능 배분, 정보 흐름, 인터페이스, 안전 요구사항 | 진행 중 |
| L3: 기초 설계 | 호모그래피 방식, 검출 거리 산정, 지연 측정 구간 | 초기 정의 |
| L4: 상세 설계 및 구현 | 연산 장치, MCU, 메시지 세부 사항, 전원, 장착, 개념 검증 | 계획 단계 |

설계 학기에는 요구사항, 상위 구조, 기초 설계를 다룹니다. 이후 구현 학기에는 실험 차량의 실제 속도, 제동 거리, 시스템 지연을 측정해 정지 성능을 평가할 예정입니다.

## 가림 시나리오와 운행설계영역

학교 주변이나 캠퍼스에서 정차 또는 주차한 차량이 보행자를 가려 차량 카메라로 보기 어려운 상황을 다룹니다. 인프라 카메라는 보행자를 먼저 관찰할 수 있도록 가림 구역의 반대편에 설치하는 방안을 제안했습니다.

| 운행 조건 | 초기 범위 |
| --- | --- |
| 장소 | 학교 주변 또는 캠퍼스의 통제 가능한 도로 |
| 조명 | 충분한 시야를 확보할 수 있는 주간 |
| 날씨와 노면 | 맑은 날씨와 건조한 포장도로 |
| 차량 움직임 | 직선 구간에서의 저속 주행 |
| 초기 범위 밖의 조건 | 야간, 악천후, 교차로, 혼합 교통 |

**운행설계영역(ODD)**은 시스템이 작동하도록 설계한 운행 조건의 범위입니다.

현재 메시지에 포함할 정보는 **`x`, `y`, `confidence`, `timestamp`**입니다. 엣지 장치가 이 객체 상태 정보를 차량으로 직접 보냅니다. 구체적인 메시지 형식, 좌표 규약, 동기화 방식, 통신 프로토콜은 아직 확정하지 않았습니다.

## 호모그래피를 이용한 보행자 위치 추정

보행자의 바운딩 박스를 검출한 뒤 **바운딩 박스의 하단 중앙점 `(u, v)`**을 지면 접촉점의 추정값으로 사용합니다. 보정한 호모그래피를 이용해 이 점을 도로 좌표 `(x, y)`로 투영하는 방식입니다.

<p class="design-equation"><code>s [x, y, 1]ᵀ = H [u, v, 1]ᵀ</code></p>

영상의 기준점과 도로 평면의 기준점을 대응시켜 `H`를 추정합니다. 보행자의 지면 접촉점이 보정한 도로 평면 위에 있다는 가정을 사용합니다. 보정과 위치 오차 측정은 향후 진행할 계획입니다.

## 동일 조건의 E2E 비교

<MediaSlot id="v2i-comparison" lang="ko" />

| 항목 | 차량 카메라만 사용하는 기준 시스템 | V2I 정보를 추가한 제안 시스템 |
| --- | --- | --- |
| 입력 | 차량 카메라와 차량 상태 | 차량 카메라, 차량 상태, 인프라 객체 상태 |
| 계획 구조 | 시각 인코더와 E2E 계획 모듈 | 시각 인코더, 객체 상태 인코더, 경량 융합, E2E 계획 모듈 |
| 출력 | Waypoint와 목표 속도 | Waypoint와 목표 속도 |
| 통제 조건 | 동일한 실험 차량, ODD, 속도, 학습 조건, 제어기 | 동일 조건 |

인프라 객체 상태를 추가했을 때의 효과를 확인하는 비교입니다. 기반 모델, 학습 설정, 시험 횟수, 수치로 정할 운행 제한은 실험 전에 확정할 예정입니다.

## 최소 검출 거리 요구사항

기초 설계에서는 필요한 대응 거리를 시스템 지연, 제동 거리, 안전 여유 거리로 나눕니다.

<p class="design-equation"><code>d_req = v · T_system + D_brake(v) + M</code></p>

| 항목 | 거리 산정에서의 의미 |
| --- | --- |
| `v · T_system` | 전체 시스템 지연 동안 차량이 이동하는 거리 |
| `D_brake(v)` | 선택한 속도에서의 제동 거리로, 실험 차량에서 측정할 값 |
| `M` | 보행자와 확보해야 하는 안전 여유 거리 |
| `d_req` | 보행자 정보를 받아 제때 정지하기 위해 필요한 최소 거리 |

설계 학기에는 속도와 지연의 기준, 제동 거리와 여유 거리의 측정 방법을 정합니다. 구현 학기에는 측정값을 대입해 이 요구사항을 평가할 예정입니다.

## 지연 측정과 평가 계획

측정 구간은 **카메라 영상 획득 → 보행자 검출 → 호모그래피 → V2I 전송 → 융합 및 E2E 계획 → 제어 명령 생성**입니다. 각 단계의 입출력 타임스탬프를 기록해 전체 지연 **`T_system = t6 − t0`**을 구합니다. **P50, P95, 최대 지연**을 정리해 거리 산정에 사용할 계획입니다.

| 평가 항목 | 측정 계획 |
| --- | --- |
| 인지 선행 정도 | 인프라 카메라가 보행자를 얼마나 먼저 검출하는지 거리와 시간으로 측정 |
| 정보 전달 | 영상 획득부터 제어 명령 생성까지 단계별 지연과 전체 지연 측정 |
| 반응 선행 정도 | 두 시스템의 감속 시작 거리와 시간 차이 측정 |
| 안전 결과 | 최소 충돌 예상 시간(TTC)과 충돌 여부 확인 |

## 차량 통합과 다음 단계

차량 인터페이스는 전방 카메라 입력, V2I 객체 상태 수신, waypoint 및 목표 속도 출력으로 설계했습니다. 안전 요구사항에는 **비상 정지(E-stop), 명령 타임아웃, 기본 출력 0, 워치독**이 포함됩니다. 이 안전 기능들은 향후 구현하고 시험할 예정입니다.

다음으로 시스템 요구사항과 하위 시스템별 기능 배분을 마무리하고, 카메라 보정 방식과 타임스탬프 규약, 수치로 정할 시험 조건을 정의합니다. 연산 장치, MCU, 제어 인터페이스, 전원, 장착 방식은 상세 설계에서 결정합니다. 이후 개념 검증과 동일 조건의 주행 비교 시험을 진행할 계획입니다.
